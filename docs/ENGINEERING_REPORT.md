# Engineering report — 4 October 2026

## Continuation on 4 October 2026

The numbered foundation report below describes the state before this continuation. Current work added tenant ownership to 28 school tables, a default-school backfill migration, school-slug login, tenant-scoped ORM reads and writes, a platform plan/subscription/audit schema and administration API, a platform dashboard and onboarding form, entitlement and seat checks, a separate SaaS payment path, and tenant-specific private file keys with S3-compatible production storage. A platform owner is created only through an explicit environment-driven command. Tests now include two-school isolation, platform onboarding, subscription limits, mocked SaaS payment/webhook behavior, and storage key checks.

Verification completed on disposable databases: 43 backend tests passed on SQLite and 43 on local PostgreSQL; Alembic upgrade and schema check passed on both during the migration rehearsal; a populated synthetic legacy PostgreSQL schema and copied legacy SQLite database retained their rows and received tenant IDs. Offline PostgreSQL SQL generation also passed. The supplied Render database was not contacted. A real Razorpay test transaction/webhook, recurring billing/refunds, full route-by-route resource authorization, complete screen redesign, comprehensive device and accessibility QA, and Render deployment remain open. **Do not onboard customer schools or claim production readiness.**

This is an **incremental implementation**, not completion of the multi-tenant SaaS brief. The multi-tenant implementation still has release-blocking authorization, payment, UI and deployment gaps; it must not be opened to customer schools.

1. **Architecture changes:** Preserved FastAPI, SQLAlchemy, static HTML, and existing services. Added a shared UI theme/shell foundation and documented the remaining architecture gaps.
2. **Database changes:** No customer database changed. PostgreSQL URL normalization selects the installed `psycopg2` driver. Production startup no longer calls `create_all()`; `/ready` checks database connectivity.
3. **Migrations:** `migrations/versions/54cd203053ec_baseline_existing_erp_schema.py` creates the 29-table legacy schema. `598ecbb48c43_normalize_legacy_constraints.py` backfills four nullable legacy fields and enforces their current model constraints. `scripts/verify_legacy_schema.py` checks an existing database before stamping the baseline.
4. **API changes:** Added `/ready`. Private download endpoints now require a bearer header and a matching document, submission, assignment, or study-material record. Fee history, fee summary, and receipts have stricter role/owner checks.
5. **Authentication and authorization:** Removed demo-password aliases and query-string JWT acceptance. Existing five school roles remain. This is not a complete route-by-route authorization review.
6. **Multi-tenancy:** Not implemented. The data model lacks `tenant_id`; no second school should be onboarded.
7. **SaaS:** Platform roles, plans, subscriptions, usage limits, entitlements, and platform admin are not implemented.
8. **Billing:** Existing school fee checkout now computes the balance server-side, verifies Razorpay signature plus provider order/payment details, checks intended fee/student/user and captured amount, and avoids recording the same payment ID twice. SaaS billing and webhooks are not implemented. A full reconciliation/refund strategy for multiple captured orders remains open.
9. **UI/UX:** Rebuilt login, shared role navigation, header controls, theme selector, and shared styling. The design system is linked from 68 full HTML pages; six HTML fragments do not have a document head. Replaced dashboard stat emoji icons and common action-prefix emoji via the shared renderer. Screen-specific workflows remain to be redesigned and visually audited.
10. **Design system:** Added semantic light/dark tokens, control, table, card, badge, focus, motion, and responsive rules in `frontend/css/design-system.css`, documented in `docs/DESIGN_SYSTEM.md`.
11. **Responsive/mobile:** Shared navigation drawer and layout adjustments remain available below 992px; added responsive page spacing. Browser inspection covered an approximately 662px viewport. Requested 360–1280px checks remain open.
12. **Security:** Removed embedded JWT/Razorpay defaults and Compose secrets; CORS now uses exact configured origins; fixed upload path containment; guarded file downloads; removed URL tokens; escaped data in shared notification and dashboard rendering. Existing localStorage token use, local file storage, and many unreviewed route/HTML interpolations remain risks. Rotate previously exposed secrets.
13. **Tests executed:** `pytest` against a newly seeded temporary SQLite database; Python `compileall`; `node --check`; `git diff --check`; Alembic migration and check on new and copied legacy SQLite databases; offline PostgreSQL SQL generation; manual browser inspection of login and representative admin pages.
14. **Test results:** 25 backend tests passed, one dependency deprecation warning. The checked-in sample database produced two old demo-fixture failures when copied for testing. A Docker build could not run because the local Docker daemon was unavailable. No live PostgreSQL, Razorpay, Render, or cross-tenant test has run.
15. **Files changed:** Backend config, auth, permissions, documents, fee routes/schema, report service, main app, file service and tests; Docker/Compose/requirements; shared frontend CSS/JS, login, and HTML stylesheet references; Alembic and verification script; README and docs. Two pre-existing tracked deletions were left untouched.
16. **Environment variables:** Production needs `ENVIRONMENT=production`, PostgreSQL `DATABASE_URL`, random `SECRET_KEY`, exact `ALLOWED_ORIGINS`, and `PORT` from Render. School fee online payments additionally need `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`. Future SaaS webhooks and object storage require their own secrets and S3 settings.
17. **Deployment:** See `docs/MIGRATIONS.md` and `docs/DEPLOYMENT.md`. Rehearse the legacy migration on a PostgreSQL staging copy and verify backup recovery before any production release. No Render deployment was performed.
18. **Known limitations:** No tenant isolation, platform admin, subscriptions, SaaS billing, S3 storage, full responsive/accessibility QA, or complete ERP route audit. The UI pass is a foundation across pages, not the full screen-by-screen modernization requested.
19. **Next steps:** Design and migrate tenant ownership with default-school backfill; enforce tenant and resource access in every route/service; prove two-school isolation; add platform identity and subscription services; build separate idempotent SaaS billing; move private files to tenant-scoped object storage; complete all screen and device QA; stage and then deploy only after security and rollback gates pass.
